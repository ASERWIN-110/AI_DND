# Prompt 流表

本文按“玩家视角聊天”整理当前架构里的 prompt 拼合关系。表内不展开工具返回 JSON，工具新产生的输出只用中文工具名表示，例如 `system.action.resolve` 的新增输出写作“行动结算”。

## 记号

| 记号 | 含义 |
| --- | --- |
| `玩家输入` | 玩家在聊天框输入的本轮文本，或玩家在 UI 中提交的操作文本。 |
| `固定功能性prompt` | 代码、循环配置、工具模板、角色卡 system/post-history 中固定写死或可配置的功能性提示。 |
| `参考文本` | 存档数据库、reference_texts、规则量尺、世界书、RAG 文档中作为参考而不是玩家本轮输入的文本。 |
| `数据库快照` | 当前聊天数据库中的 NPC、地图、物品、技能、状态、任务、阵营、背包等结构化记录。 |
| `聊天历史` | 最近聊天消息或压缩后的历史摘要。 |
| `A + B` | A 和 B 被拼合进同一层 prompt 或同一层上下文包。 |
| `压缩(A)` | A 不原样传递，只传递摘要、选中片段、context envelope、trace 引用或预算后的 promptContext。 |

当前网页聊天默认走 Agent Loop：`/v1/app/chats/{id}/send -> system.agent_loop.run_config_turn`。只有传入 `options.agentLoop=false` 或 `options.mode=direct` 时，才走直接聊天 prompt builder。

## 默认 Agent Loop Prompt 流

| 工具名 | 实际工具/阶段 | 工具功能与作用 | 输入 | 输出 | 上游直接工具 | 下游直接工具 |
| --- | --- | --- | --- | --- | --- | --- |
| 玩家输入 | 前端聊天框 | 本轮玩家文本来源。 | 玩家键入文本 | 玩家输入 | 无 | Agent循环、输入接收 |
| Agent循环 | `system.agent_loop.run_config_turn` | 读取当前循环配置，按步骤运行本轮模块，并把最终叙事写回聊天。 | 玩家输入 + 固定功能性prompt(循环配置) + 聊天历史 | 玩家输入 + Agent循环 | 玩家输入 | 回合快照、输入接收、叙事生成 |
| 回合快照 | `turn.snapshot` | 保存回合开始时的聊天、工具列表和 trace 起点。 | 数据库快照 + 工具列表 | 回合快照 | Agent循环 | 基础加载、调试汇总 |
| 输入接收 | `input.intake` | 规范化本轮输入，找出 latest user message。 | 玩家输入 + 聊天历史 | 输入接收 | Agent循环、玩家输入 | 角色控制、意图路由、世界书激活 |
| 角色控制 | `system.actor_control.get_context` / `actor.control_context` | 确认玩家当前控制哪个主角，避免把普通发言当成世界事实。 | 玩家输入 + 数据库快照 + 固定功能性prompt(角色控制规则) | 角色控制 | 输入接收 | 基础加载、上下文完整度、叙事生成 |
| 基础加载 | `baseline.load` | 读取小体量基础事实、角色卡名、最近消息和关键词。 | 聊天历史 + 数据库快照 + 角色卡笼统设定 | 基础加载 | 回合快照、角色控制 | 世界书激活、RAG引导、上下文完整度 |
| 意图路由 | `route.intent` | 用可编辑关键词把玩家输入路由到行动、战斗、社交、移动、观察等候选类型。 | 玩家输入 + 固定功能性prompt(路由关键词) | 意图路由 | 输入接收 | 处理器编排、上下文完整度、叙事生成 |
| 世界书激活 | `worldbook.activate` | 根据玩家输入和历史激活小段世界书，不负责承载完整设定。 | 玩家输入 + 聊天历史 + 基础加载 + 参考文本(世界书) | 世界书激活 | 基础加载、输入接收 | RAG引导、叙事生成 |
| RAG引导 | `rag.guidance` | 把世界书结果转成检索词、collection hints 和 metadata filters。 | 世界书激活 + 玩家输入 + 基础加载 | RAG引导 | 世界书激活 | 定向检索、上下文完整度、叙事生成 |
| 定向检索 | `retrieval.targeted` | 规划本轮应该读哪些 RAG/数据库内容；基础阶段本身不硬编码具体库。 | 玩家输入 + RAG引导 + 基础加载 | 定向检索 | RAG引导 | 上下文完整度 |
| 上下文完整度 | `system.context_completeness.resolve_context` | 检查当前 prompt 是否缺关键上下文，并调用/回退到上下文规划。 | 玩家输入 + 角色控制 + 意图路由 + RAG引导 + 数据库快照 + 参考文本 | 上下文完整度 | 定向检索、意图路由 | 上下文规划、处理器编排、叙事生成 |
| 上下文规划 | `system.context_planner.plan_context` | 在 token 预算内选择当前场景 NPC、地图、任务、记忆、RAG 和最近消息。 | 上下文完整度 + 数据库快照 + 聊天历史 + 参考文本 | 上下文规划 | 上下文完整度 | 行动结算、说服结算、战斗结算、叙事生成 |
| 处理器编排 | `resolver.orchestration` | 把意图路由转为候选 resolver，不直接写状态。 | 玩家输入 + 意图路由 + 固定功能性prompt(允许 resolver 列表) | 处理器编排 | 意图路由、上下文完整度 | 裁决层、行动结算、说服结算、战斗结算 |
| 裁决层 | `adjudication` | 接收候选 resolver 或可编辑裁决模板，形成裁决草案。默认具体判断仍交给 resolver 工具。 | 处理器编排 + 上下文规划 + 固定功能性prompt(裁决模板) | 裁决层 | 处理器编排 | 影响计划、叙事生成 |
| 行动结算 | `system.action.resolve` | 把开放式行动转成行动计划、检定、工具调用提案和可申诉裁决，并可运行语义写库规划。 | 玩家输入 + 上下文规划 + 参考文本(难度/数值量尺) + 固定功能性prompt(行动计划模板) + 固定功能性prompt(语义写库模板) | 行动结算 | 处理器编排、裁决层 | 骰子检定、语义写库、影响计划、叙事生成 |
| 说服结算 | `system.persuasion.resolve` | 判断玩家话术质量、上下文难度和骰子结果如何合并。 | 玩家输入 + 上下文规划 + 参考文本(社交量尺) + 固定功能性prompt(说服判断模板) | 说服结算 | 处理器编排、裁决层 | 骰子检定、状态写入、影响计划、叙事生成 |
| 战斗结算 | `system.combat.*` | 判断开战、战斗行动、特殊战斗动作和战后影响。 | 玩家输入 + 上下文规划 + 数据库快照(战斗/角色/资源) + 参考文本(战力/动作量尺) + 固定功能性prompt(战斗模板) | 战斗结算 | 处理器编排、裁决层 | 骰子检定、状态写入、影响计划、叙事生成 |
| 骰子检定 | `game.dice.check` | 执行确定性骰子检定，不让 LLM 编造骰子结果。 | 行动结算/说服结算/战斗结算 + 固定功能性prompt(骰子参数) | 骰子检定 | 行动结算、说服结算、战斗结算 | 状态写入、影响计划、叙事生成 |
| 影响计划 | `impact.plan` | 把裁决和 resolver 结果整理成将要写入状态的影响草案。 | 裁决层 + 行动结算 + 说服结算 + 战斗结算 + 骰子检定 + 固定功能性prompt(影响计划模板) | 影响计划 | 裁决层、骰子检定 | 语义写库、影响路由校验、叙事生成 |
| 语义写库 | `Semantic Database Write Planner` / `system.data.quantify_text` | 把影响草案中的数据库写入重新归类到合适工具、字段或扩展集合，避免按字面误写。 | 玩家输入 + 影响计划 + 行动结算 proposals + 数据库快照 + 参考文本 + 固定功能性prompt(语义写库规则) | 语义写库 | 行动结算、影响计划 | 影响路由校验、状态写入、叙事生成 |
| 影响路由校验 | `impact.route_validate` | 检查影响草案和语义写库结果应该交给哪些写入工具，以及哪些工具被阻止。 | 影响计划 + 语义写库 + 固定功能性prompt(工具权限/允许列表) | 影响路由校验 | 影响计划、语义写库 | 状态写入 |
| 状态写入 | `system.*.patch_*` / `system.*.upsert_*` / `system.time.*` / `system.slot_use.*` / `system.data.*` | 写入 NPC、地图、物品、技能、状态、任务、时间、关系、阵营、背包或扩展数据库等世界状态。 | 影响路由校验 + 语义写库 + 行动结算/说服结算/战斗结算 + 骰子检定 | 状态写入 | 影响路由校验、语义写库、骰子检定 | NPC反应、环境反应、叙事生成、记忆后处理 |
| NPC反应 | `system.npc_behavior.resolve` / `reaction.npc` | 在需要时根据影响结果规划 NPC 反应；默认是 no-op 检查点。 | 状态写入 + 裁决层 + 上下文规划 + 数据库快照(NPC) + 固定功能性prompt(NPC行为模板) | NPC反应 | 状态写入、影响计划 | 环境反应、叙事生成 |
| 环境反应 | `system.environment_behavior.resolve` / `reaction.environment` | 在需要时根据影响结果规划环境、机关、灾害或场景反应；默认大多 no-op。 | NPC反应 + 状态写入 + 上下文规划 + 数据库快照(地图/场景) + 固定功能性prompt(环境行为模板) | 环境反应 | NPC反应、状态写入 | 叙事生成 |
| 叙事生成 | `narrative.render` | 把玩家输入、上下文、裁决和影响结果拼成玩家可读叙事。启用 LLM 时会真正调用模型。 | 固定功能性prompt(叙事格式) + 玩家输入 + 角色控制 + 意图路由 + 上下文规划 + 世界书激活 + RAG引导 + 裁决层 + 影响计划 + NPC反应 + 环境反应 | 叙事生成 | 上下文规划、裁决层、影响计划、NPC反应、环境反应 | 结构化解析、记忆后处理、前端显示 |
| 结构化解析 | `structured.parse` / `postprocess.memory` | 从最终叙事中解析状态栏、小地图、背包、技能栏等结构化块；运行回合后自动处理。 | 叙事生成 + 固定功能性prompt(结构化界面规则) | 结构化解析 | 叙事生成 | 记忆后处理、前端显示 |
| 记忆后处理 | `system.chat_compression.*` / `system.character_memory.*` / `system.rag_runtime.remember` | 压缩历史、更新角色记忆或写入 runtime RAG，供后续回合检索。 | 叙事生成 + 聊天历史 + 结构化解析 + 参考文本 | 记忆后处理 | 结构化解析、叙事生成 | 以后回合的基础加载、上下文规划、RAG引导 |
| 调试汇总 | `debug.collect` | 汇总 phase、router、工具、token 风险和 trace；不应进入正式叙事 prompt。 | 压缩(Agent循环 + 各工具输出) | 调试汇总 | 所有阶段 | Tool Manager、开发调试 |
| 前端显示 | Web UI | 展示最终 assistant message、骰子、裁决、状态变化、router 气泡和 trace 链接。 | 叙事生成 + 骰子检定 + 状态写入 + 调试汇总 | 前端显示 | 叙事生成、状态写入、调试汇总 | 玩家输入 |

## 直接聊天备用路径

直接聊天不走上面的 resolver/agent-loop 链。它只用传统 prompt builder 拼接消息：

| 工具名 | 实际入口 | 工具功能与作用 | 输入 | 输出 | 上游直接工具 | 下游直接工具 |
| --- | --- | --- | --- | --- | --- | --- |
| 直接聊天生成 | `sendAppChatMessageDirect` / `buildPrompt` | 传统角色卡聊天：拼 system、世界书、RAG、历史和结构化界面 prompt 后直接调用模型。 | 固定功能性prompt(preset main + 角色卡 system) + 参考文本(世界书) + 玩家设定 + 角色卡描述 + 参考文本(RAG) + 聊天历史 + 固定功能性prompt(post-history) + 固定功能性prompt(结构化界面) + 玩家输入 | 直接聊天生成 | 玩家输入 | 结构化解析、前端显示 |

直接聊天路径适合普通角色卡聊天或调试 provider；当前项目的 AI-DND 游玩主路径应优先使用默认 Agent Loop，因为骰子、数据库、裁决、背包、地图和状态写入都在 Agent Loop 与工具层里完成。

## 压缩传递规则

| 场景 | 推荐表达 |
| --- | --- |
| 多步骤 flow 的上一步输出传给下一步 | `玩家输入 + 压缩(上一步Agent循环)` |
| 上下文规划传给叙事生成 | `玩家输入 + 压缩(上下文规划) + 世界书激活 + 裁决层 + 影响计划 + 语义写库` |
| 调试 trace 给开发者看，但不喂给模型 | `压缩(Agent循环 + 工具输出) -> 调试汇总` |
| RAG/数据库命中数量过多 | `玩家输入 + 压缩(参考文本 + 数据库快照)` |
| 后续回合复用历史 | `玩家输入 + 压缩(记忆后处理) + 最近聊天历史` |

## 关键边界

- 角色卡和 system prompt 只放宏观世界观、文风和 GM 总原则；复杂人物设定、地图、物品、技能、状态和数值量尺应进入数据库、世界书、RAG 或参考文本。
- LLM 可以判断模糊意图、话术质量、语义写库归类、叙事表达和特殊行动解释；骰子结果、确定性资源消耗、最终数据库写入和可审计状态变化应由工具完成。
- `debug.collect`、trace、router 展示气泡是调试和前端说明，不应被下游叙事 prompt 当成世界事实。
